# 017. 取得中・エラーの表示（useQuery の状態で分岐）

- ステータス: 採用

## コンテキスト

API の取得中・エラーの表示方法を決める。TanStack Query には、取得中・エラーを Suspense / Error Boundary に任せる `useSuspenseQuery` もある。

- 取得中・エラーを個別に表示する場所は、サイドバー（ページ一覧）と本文（トップ・詳細）の 2 か所
- それぞれの場所で使う GET API は 1 つずつ

## 決定

`useQuery` を使い、各コンポーネントで `isPending` / `isError` を見て表示を分ける。

- サイドバーと本文はそれぞれ単独で読み込み・失敗するため、`useSuspenseQuery` にしても Suspense / Error Boundary を場所ごとに置く必要がある。親にまとめても置く数が減らず、メリットが薄い
- 詳細画面は取得に成功しても「ページが見つからない（`null`）」の分岐が残るため、子を「取得に成功した前提」で書けるメリットも小さい
- エラーの文言を場所ごとに変えられ、分岐がコンポーネント内で完結するので読みやすく、テストもしやすい

## 検討した選択肢

- `useSuspenseQuery` + Suspense / Error Boundary: 上記の理由でメリットが薄いため不採用
