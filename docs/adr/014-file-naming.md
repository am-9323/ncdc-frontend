# 014. ファイル名の付け方

- ステータス: 採用

## コンテキスト

コンポーネントはパスカルケース、それ以外はケバブケースと、ファイル名の付け方が混在している。ルートは中身がコンポーネントだが、ケバブケースになっている。意図を明確にするため、ルールを決める。

## 決定

| 種類 | 命名 | 例 |
| --- | --- | --- |
| コンポーネント（`components/`、`features/*/components/`） | パスカルケース。フォルダ名・ファイル名をコンポーネント名と同じにする | `Button/Button.tsx`、`ContentField/ContentField.module.scss` |
| ルート（`app/routes/`） | ケバブケース | `content.tsx`、`content-layout.tsx` |
| API・hooks・関数・設定など | ケバブケース | `get-contents.ts`、`validate-content-field.ts` |

- コンポーネントは、ファイル名だけでコンポーネントだとわかるようにする
- ルートはルーターに登録するものとして、コンポーネントと区別する
- それ以外は、1 ファイルに複数の関数などが入ることもあるため、中身の名前ではなく役割を表す名前にする

## 検討した選択肢

- すべてケバブケース: 最近増えている形だが、コンポーネントのファイル名と import をすべて変える必要があり、変更が大きいため今回は不採用。大文字小文字違いを防ぐなどメリットはあるため、次は試してみたい。
- ルートもパスカルケース: 例外はなくなるが、URL に対応する画面とコンポーネントの区別がつきにくくなるため不採用
